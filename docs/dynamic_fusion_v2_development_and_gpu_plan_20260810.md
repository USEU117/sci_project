# DynamicFusion V2 开发与后续 GPU 实验计划

更新时间：2026-08-10  
适用项目：少样本工业异常检测中的视觉—文本动态融合  
当前边界：本计划只整理设计、代码和实验队列；不启动 GPU 长任务，不修改已经冻结的 DynamicFusion V1 结果。

## 1. 先给出结论

DynamicFusion V1 已经完成了接口、校准、双层路由、消融和独立验证，但效果没有达到“稳定超过强视觉分支”的预期。主要问题不是温度参数不够好，而是前面的分数校准发生了严重饱和：大量不同的视觉分数都被压到接近 1，原来的高低顺序变得难以区分。随后，熵把这种“数值贴边”误认为“模型很有把握”，路由权重便不能可靠选择更好的分支。

因此，V2 不应继续大范围搜索温度，而应依次解决四个更基础的问题：

1. 校准后仍保留强视觉分支的排序。
2. 识别“超出少量正常样本能够解释的范围”，不能把它直接当成高置信度。
3. 默认保护强视觉分支，只有文本证据通过安全条件时才允许改变结果。
4. 图像级分类和像素级定位分别设计路由，不共用一套简单判断。

## 2. V2 的输入与输出

### 2.1 输入

每张查询图像只允许读取以下内容：

- 视觉分支的图像分数 `s_v` 和像素图 `M_v`。
- 文本分支的图像分数 `s_t` 和像素图 `M_t`。
- K 张正常参考图及其固定增强视图产生的分支输出。
- 由正常参考图计算并冻结的校准参数、支持范围和稳定性统计量。
- 当前查询图像的两个分支输出之间的差异、空间集中程度和增强稳定性。

### 2.2 禁止输入

- 测试图像的真实正常/异常标签。
- 测试图像的像素掩码。
- 整个测试集的均值、方差、分位数、直方图或排序。
- 前一张测试图保存下来的记忆，除非未来单独建立并明确标注在线/传导协议。
- 看完最终测试结果后继续调阈值。

### 2.3 输出

- 图像级视觉权重 `w_I` 和融合图像分数 `s_f`。
- 像素级视觉权重图 `W_P(x)` 和融合像素图 `M_f`。
- 安全状态：`use_visual_default`、`allow_text_assist`、`out_of_support`、`calibration_warning`。
- 审计字段：参数来源、参考样本哈希、是否使用测试标签、是否使用测试集整体统计量。

## 3. CPU 优先的 V2 开发工作包

### WP1：冻结 V1 证据和建立 V2 基准

目的：保证后续修改不会覆盖失败证据，也不能通过改变旧结果让 V1 看起来更好。

操作：

1. 为 V1 配置、预测缓存、校准文件、指标和图表记录 SHA256。
2. 固定 V1 标识：图像温度 0.50、像素温度 0.20、decision margin 0.15、minimum weight 0.05。
3. 生成一份 V1 基准表，至少包含：raw visual、raw text、fixed 0.50、best fixed、V1 dynamic。
4. 为每类记录校准饱和率、校准前后 Spearman 相关性、融合前后排序变化、权重与真实分支优势的相关性。
5. 所有 V2 结果使用新 RunId 和新目录，禁止覆盖 V1。

验收：任一 V1 文件被改动时，哈希检查必须失败；V1 与 V2 可以一眼区分。

资源：CPU；预计 0.5 天。

### WP2：重新划分开发边界

目的：MVTec AD 和 VisA 已用于 V1 分析，不能继续反复看结果调 V2。

建议：

1. 首选新增 MPDD 作为 V2 开发集。
2. 首选新增 BTAD 作为独立保持集；如果授权、磁盘或格式不合适，可交换两者角色。
3. MVTec AD 和 VisA 只做冻结后的回顾验证，或者明确标注为 exploratory retrospective analysis。
4. 新数据继续采用 1/2/4-shot、3 seeds、嵌套抽样和统一 NPZ 格式。
5. 在读取最终保持集指标前，锁定全部 V2 参数和接受条件。

验收：存在独立的开发 manifest、保持集 manifest、哈希、类别/样本数量检查和数据使用声明。

资源：准备和审计主要为 CPU；分支预测需要 GPU。CPU 部分预计 0.5-1 天。

### WP3：排序保持校准

目的：避免 V1 的大量 0.999 饱和和并列分数。

先实现以下候选，全部只使用正常参考输出：

1. 带合理尺度下限的 robust z-score，尺度下限从正常视图波动而不是极小 MAD 单独决定。
2. 严格单调的正常尾部分位映射；对相同参考值增加确定性的微小排序规则，避免 ECDF 大量并列。
3. 分段线性或单调样条映射，明确限制最小斜率和最大斜率。
4. 原始分数旁路：即使校准值用于比较分支，也保留原始视觉分数用于最终排序或安全回退。

每个候选必须报告：

- 校准前后 Spearman 相关性。
- 唯一值比例和最大并列组大小。
- `p <= 0.001` 与 `p >= 0.999` 的比例。
- 正常参考视图的稳定性。
- raw visual 与 calibrated visual 的 Image AUROC 差值，只能作为旧缓存诊断，不能用于新参数选择。

最低验收：强视觉分支的校准前后排序相关性接近 1；不再出现接近 100% 的边界饱和；数值全部有限。

资源：冻结缓存可用时只需 CPU；预计 1-2 天。

### WP4：超出支持范围检测

目的：区分“模型确实有把握”和“分数已超出正常参考能够解释的范围”。

建议特征：

- 查询分数到正常最大值/高分位数的距离。
- 该距离相对于参考视图波动的倍数。
- 不同确定性视图下分数是否稳定。
- 校准映射是否触及边界。
- 图像分数与像素图尾部统计是否矛盾。
- 两个分支是否在方向或空间位置上严重冲突。

输出：`out_of_support_visual`、`out_of_support_text` 和连续的支持可信度，不把它们直接等同于 anomaly probability。

验收：合成极端值、常数输入、极小 MAD、NaN/Inf 和全零像素图测试全部通过。

资源：CPU；预计 0.5-1 天。

### WP5：视觉默认的安全路由器

目的：文本证据不足时保持强视觉分支，减少负迁移。

第一版先使用可解释规则，不急于训练神经网络：

1. 默认 `w_I = 1`、`W_P(x) = 1`，即保留视觉结果。
2. 只有文本分支的正常参考稳定性通过阈值时，才允许进入下一步。
3. 只有两分支存在可解释互补，而不是单纯尺度不同或背景扩散时，才允许文本辅助。
4. 图像级修改必须满足更严格的条件，因为任意样本权重变化都可能破坏全局排序。
5. 像素级可允许更小范围的文本补充，但必须限制作用区域、最大幅度和背景激活。
6. 任一校准警告、支持范围警告或非有限值都触发视觉回退。

后续如果规则能够稳定工作，再将同样特征输入一个很小的逻辑回归或 MLP；训练数据只能来自新的 V2 开发集。

验收：所有失败注入都会回退；文本输入被置乱或置零时不应比 raw visual 明显更差；图像级最坏类别退化受到预先设定的上限约束。

资源：规则版 CPU；小路由器训练可在 CPU 或少量 GPU 上完成；预计 1-2 天。

### WP6：图像级和像素级彻底分开

图像级路由关注：

- 样本总分的排序稳定性。
- 两分支图像分数差异和校准支持度。
- 不同正常视图产生的图像分数波动。
- 是否触发强视觉保护。

像素级路由关注：

- 热图的空间集中度、连通区域、边界和背景响应。
- 两个热图在高响应区域的重合与冲突。
- 文本热图是否比视觉热图更扩散。
- 局部权重的平滑性和最大修改幅度。

禁止从图像级 `w_I` 简单复制出整张像素权重图，也禁止只用一个温度同时优化两种任务。

验收：两个路由器具有不同输入特征、配置项、日志和消融开关。

资源：CPU；预计 1 天。

### WP7：缓存级单元测试和最小消融

单元测试：

- 样本 ID 顺序不一致时拒绝运行。
- 像素图尺寸不同且无法确定性对齐时拒绝运行。
- NaN/Inf、空参考集、K 值错误时拒绝运行。
- 不允许测试标签或测试掩码进入校准/路由函数签名。
- 所有输出范围、形状和可重复性检查。
- 安全回退路径逐项覆盖。

最小消融矩阵：

1. raw visual。
2. raw text。
3. fixed 0.50 fusion。
4. development-only best fixed weight。
5. V1 calibration + V1 router。
6. rank-preserving calibration + fixed fusion。
7. 上述方案 + out-of-support flag。
8. 上述方案 + safe visual fallback。
9. image-only router。
10. pixel-only router。
11. complete split image/pixel router。
12. post-hoc oracle selector，仅作理论上界，不是可部署方法。

资源：有分支缓存时 CPU；预计 1-2 天。

### WP8：冻结和独立验证

冻结前只看 V2 开发集。冻结内容包括：

- 校准类型和全部参数。
- 支持范围定义。
- 图像/像素路由特征。
- 所有阈值、权重上下限和回退规则。
- 允许报告的主要指标和失败指标。

冻结后才运行保持集，再运行 MVTec AD 和 VisA 回顾验证。报告内容：

- Image AUROC/AP/F1-max。
- Pixel AUROC/AP/AUPRO。
- 相对 raw visual 的逐类别差值。
- 负迁移类别比例和最坏退化。
- 校准排序、饱和、权重—分支优势相关性。
- 3 seeds 的均值、样本标准差和配对置信区间。

V2 最低通过条件不是“某一个平均指标更高”，而是：不再发生大面积饱和；图像级无材料性整体退化；像素收益能在保持集重复；路由权重比 V1 更能反映真实分支优势；全部泄漏字段为 false。

## 4. 后续需要 GPU 的训练与推理

### 队列 A：先补齐已经承诺的结果

1. PromptAD MVTec 剩余 5 个 seed-shot 组合。
   - 优先恢复当前未完成的 seed 1 / K=2。
   - 随后 seed 1 / K=4。
   - 最后 seed 2 / K=1、K=2、K=4。
   - 目的：把 PromptAD 从 4/9 补到 9/9，才能计算三 seed 均值和标准差。

### 队列 B：近期方法 Gate A

每个 Gate A 只跑一个类别、一个 seed、一个 shot，确认以下内容后才扩展：

- 官方代码、权重和许可证可用。
- 输入预处理和参考样本来自统一 manifest。
- 输出可以转成统一 NPZ。
- 类别、样本数、分数方向、像素图尺寸和指标正确。
- `target_normal_tuning`、`base_dataset_training`、`single_query_adaptation`、`transductive_test_statistics` 均有明确记录。
- RTX 3060 Laptop 6 GB 可运行，或有不改变方法身份的官方 CPU/offload 路径。

建议顺序：

1. ReMP-AD：原计划核心多模态少样本方法。
2. AdaptCLIP：2026 方法，但先审计基础训练域和 checkpoint。
3. SubspaceAD：2026 强视觉方法，优先级高；官方 DINOv2-G 可能超过 6 GB，允许官方 offload，但不能偷偷换成小模型后仍按原方法命名。
4. FastRef + AnomalyDINO：2026 查询原型细化，检查是否逐图独立、是否使用跨查询统计。
5. AnoPLe：多类少样本提示学习，资源和协议通过后再做。
6. AA-CLIP 或 DLVP-CLIP：二选一做文本分支替换小实验，用于判断 V1 的问题有多少来自 AnomalyCLIP 分支本身。

### 队列 C：通过 Gate A 后的正式矩阵

只有 Gate A 通过的方法才进入：

- MVTec AD：15 类 × 1/2/4-shot × 3 seeds。
- VisA：12 类 × 1/2/4-shot × 3 seeds。
- 统一保存分支预测，便于后续不占 GPU 的融合消融。
- 每个方法独立 RunId、日志、checkpoint 信息、manifest 哈希和完成标记。

### 队列 D：V2 新数据的分支缓存

1. 为 MPDD/BTAD 生成 1/2/4-shot、3 seeds manifest。
2. 运行 AnomalyDINO 和 AnomalyCLIP，导出开发集和保持集预测缓存。
3. 如果文本分支替换 Gate A 通过，再导出一个新文本分支缓存。
4. V2 路由本身优先在缓存上运行，通常不需要长期占用 GPU。

## 6. 推荐的执行顺序

1. 当前至 GPU 窗口前：完成 WP1-WP7 的 CPU 代码、文档、测试和干跑。
2. GPU 窗口开始：先补齐 PromptAD，不让旧矩阵一直残缺。
3. 按 ReMP-AD、AdaptCLIP、SubspaceAD、FastRef 顺序完成 Gate A。
4. 只扩展通过 Gate A 且协议可公平比较的方法。
5. 同期为 MPDD/BTAD 生成必要的分支缓存。
6. 在新开发集完成 V2 选择并冻结。
7. 最后一次性运行保持集、MVTec AD 和 VisA，不再根据最终结果回头调参。

## 7. 论文如何随着结果升级

- 如果 V2 在不破坏图像排序的前提下稳定提高定位：论文主线为“安全、可解释的动态融合”。
- 如果 V2 只接近视觉分支但明显减少最坏退化：主线改为“什么时候融合、什么时候回退”的风险控制。
- 如果 V2 仍明显落后：保留完整失败链，把论文定位为严格复现、泄漏审计与融合失效分析；不能删除不利类别。
- ReMP-AD、AdaptCLIP、SubspaceAD、FastRef 未通过 Gate A 前只进入 Related Work 和待完成说明，不能进入本地数值排名。

## 8. 目前明确不做的事

- 不改写 V1 的冻结结果。
- 不使用已经看过的 MVTec/VisA 最终标签继续调 V2。
- 不为了凑论文数字直接复制其他论文表格。
- 不让失败的 Gate A 自动进入长队列。
- 不为了适配 6 GB 显存而无说明地更换关键 backbone 或 checkpoint。
- 不在本计划生成时启动 GPU。
