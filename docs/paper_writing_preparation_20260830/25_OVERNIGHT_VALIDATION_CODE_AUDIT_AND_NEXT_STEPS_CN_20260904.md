# 夜间验证复核：负结果保留，整族否定结论暂不成立

日期：2026-09-04  
范围：只读检查报告、配置、源码与结果 JSON；用 CPU 合成张量做最小复现。没有修改训练代码，没有重跑训练，没有访问新的测试集。  
本文件是独立审计意见，不覆盖夜间原始记录。

## 1. 核心结论

**本次 SCAIF 实现没有超过 A1，这个负结果应保留。但“实现正确、稀疏约束已生效、整个早期融合家族被证伪”不能由现有证据支持。**

最重要的发现是：`SCAIF.refine()` 返回的 gate 已经 detach，训练却从这些 gate 计算稀疏损失。该项只有数值，没有对参数的梯度。夜间报告以“提高稀疏惩罚仍然门饱和”解释机制失败，这一归因不成立。

此外，训练只监督 patch grid 的上半部分，两个关键控制无法执行，原始 private features 没有独立保留，Stage0 oracle 存在 GT 掩膜拼接和分数尺度混杂。因此应先做一次限定的纠错复核，不进入 Stage2，也不立刻开启另一轮无约束搜索。

## 3. 已确认的实现问题

### P0-1：gate 稀疏惩罚梯度被切断

位置：

- `scripts/innovation_v12_new_observables/scaif_common.py:204`：`gs.append((gd.detach(), gc.detach()))`。
- `scripts/innovation_v12_new_observables/run_r3_ef_scaif.py:141`：从 `gs` 计算 `gmean`。
- 同文件第 147 行将 `gmean` 加入训练损失。

CPU 合成张量最小复现：

```text
sparse_penalty_requires_grad False
max_gradient_change_lambda_0_to_100 0.0
```

解释：分割损失仍可训练 gate；失效的是稀疏惩罚这一路梯度。不能说整个 gate 没有学习，也不能说稀疏约束已经尝试且无效。

修复要求：训练接口返回带计算图的 gate；日志/统计另行 detach。新增单元测试：仅对稀疏损失反传时 gate 参数梯度非零，改变惩罚权重后参数梯度必须改变。

### P0-2：512 个 query patch 固定取上半幅

位置：`run_r3_ef_scaif.py:124,127,130`。

`qflat[:, :QSUBS]` 且 `QSUBS=512`，在 32×32 row-major grid 中恒等于第 0–15 行。不是全图随机抽样。GT 与 A1 对照也同样切片，因此没有标签错位，但下半幅异常从未直接进入 query 监督损失；下半幅可能通过邻域/support 间接影响前向，不应说完全不参与计算。

最小复现行号为 `[0,1,...,15]`。

修复要求：固定种子、全图均匀或预注册的正负分层采样，同一索引同时作用于模型、标签与 A1 reference。记录累计覆盖图和异常 patch 命中率。

### P1-3：两个“已就绪”机制对照会报错

CPU 直接调用 `PairBlock.forward` 得到：

```text
no_support: mat1 and mat2 shapes cannot be multiplied (1024x64 and 66x32)
shuffled: expand 的输入为 5 维，而目标尺寸为 4 维
```

原因：no_support 去掉两项距离后，gate 输入维度由 66 变为 64，但线性层没变；shuffled offset 张量多出一维。

另外，实际可训练参数数为：

```text
main       255236
dino_only  127618
clip_only  127618
```

不符合配置中的“参数差异在 5% 内”。冻结一半参数不是参数量匹配的单分支控制。

修复要求：所有控制在训练前先通过 forward/backward、参数计数、score shape、有限数值 smoke test。不能用全局 gate 饱和推断 shuffled 必然无差别，因为 cross residual 内容仍可能依赖另一分支。

### P1-4：没有按原设想独立保留 private stream

原 doc23 的检测表征包含原始 D/C 与交互残差；实际 `scaif_common.py:201–205` 只拼接归一化后的 `D+gΔD`、`C+gΔC`。残差结构里存在 D，并不等于最终表示有独立、未受修改的 D 通道。

此外，`g≤0.2` 只限制系数，不限制 `||gΔ||`。解码器输出可增长，weight decay 不是硬幅值约束。故零门恒等测试不能证明训练后的 private evidence 被保护。

修订设计应区分：

1. 严格保留的原始 A1 表征/分数路径；
2. 单独的交互残差路径；
3. 对残差范数或相对原特征幅值的明确限制。

注意：即使保留原通道，后续整体拼接/归一化仍可能改变 KNN 排序；不能承诺“保留通道就保证不掉点”。

## 4. 需要修订或进一步验证的设计问题

- **BCE logits 无中心项。** `s=d²/2≥0`，代码使用 `BCEWithLogits(10*s, y)`，对应概率永远 `≥0.5`。正常样本无法获得负 logit。这不证明全部退化由它导致，但与期望的正常/异常判别不匹配。建议预注册源域校准的 `a*(s-b)`，或适合距离的 margin/ranking loss；不能用目标异常标签选择 b。
- **支持距离两端尺度不同。** support 投影 `su/cv` 被 normalize，query 投影 `ud/uc` 没有同样 normalize 就进入 cdist。即使输入同一个 token，该距离也未必为零。需统一尺度并建立 identical-token distance 单测。
- **按类别顺序训练，而非跨类混合。** 每个源类连续训练约 120 步，最后一类训练完即评估。可能存在顺序效应/遗忘，应作为未排除解释，而不是已证明根因。
- **branch-drop 只在配置中声明。** 当前 `train_step` 未见对应随机分支丢弃；应实现或明确记录协议删除。
- **没有保存训练 checkpoint。** 当前 CLI 只写结果 JSON，无法直接对同一权重复算机制指标。纠错运行应保存权重、配置 hash、代码 revision 与逐步日志。
- **汇总饱和值不完整。** `MECHANISM_AUDIT.json` 对各 shot 都写入第一个 fold 的 0.941508；逐 fold 原始 JSON 实际为约 0.663–0.974，应分 fold 汇总。

## 5. Stage0 的大 oracle headroom 不能当成已证实互补性

位置：`run_r3_ef_stage0_probe.py:197–229`。

实际 oracle：正常像素保持 A1，仅在 GT 缺陷组件内部替换为某专家的分数。不同专家使用未经共同校准的距离，代码还直接把距离放入 BCE 风格损失。这使 headroom 同时包含：

- 精确 GT 边界的特权；
- 不同专家的数值尺度差异；
- 真正的专家排序信息。

三者目前没有被分离。一个只有尺度差、没有任何新信息的专家，也能产生 headroom。最小反例：

```text
标签 y = [0,1,0,1]
A1分数 = [0.10,0.15,0.20,0.25]
专家分数 = 2*A1分数
A1 AP = 专家 AP = 0.833333
只在 GT 正像素拼接专家分数后 AP = 1.0
```

因此 `+0.3885` 不能用于声称“存在约 0.39 的可学习互补增益”。它是当前特权拼接程序的结果，也不是对任意实现可达收益的严格上界。

纠正方式：先加 A1复制、A1单调缩放、打乱对应三个空信息控制；专家用同一正常校准规则；候选区域须由无标签图像/分数生成，替换必须连同区域中的正常像素一起作用；训练阶段和验证阶段按图像/类别分离。若 null control 也有巨大 headroom，先停止用该 oracle 做入场判断，不训练 router。

其他 Stage0 记录问题：

- 代码实际建立 12 张 map，oracle 候选是 7 个单分支层 map，不是报告中的 14 个；72 是 12 个 D/C 层对乘以 6 类，不是 72 个不同层对。
- FULL 将同分支 raw 多层先拼接再归一化，未逐层归一化；不足以否定所有等权多层基线。
- 原始特征 parity 超过 `1e-5`，报告改用 Pixel-AP 差作为操作门；当前 doc23 与冻结协议仍保留原要求。应补明确 amendment，不应称原门全部满足。
- Pixel-AP 接近不等于 score map 逐像素一致，也不能单凭此认定 raw 差异来源一定是 GPU 非确定性。

## 6. 后续建议：限定纠错，不无限续命

### 阶段 A：只修确定性问题并验证，不跑正式矩阵

1. gate 稀疏项恢复梯度，随机全图 patch 采样；
2. 统一 support/query 距离定义；
3. 修复所有控制 forward/backward 与参数量匹配；
4. 修正 oracle 的空信息控制；
5. 保存 checkpoint 和完整训练日志；
6. 对当前文档中的“整族关闭/实现正确/稀疏约束无效”改为受限结论。

验收：训练单测全部通过，稀疏项梯度非零，整幅图可被采样，控制不报错，A1与静态基线复现。

### 阶段 B：一次 bugfix-only 复核（需批准执行）

不加层、不加宽、不换 backbone、不扫超参。固定原始层对和预算，仅修已确认实现错误，并明确哪些修复改变实验行为。跑同一 MPDD development seed0 × shot1/2/4，保留旧结果并标记新版本为 correction run。

如果主模型仍显著低于 A1/自身静态控制，停止本实现，不做 Stage2。若出现稳定改善，才补完整机制控制；进入更大验证前仍必须满足原 doc23 的 A1/strongest-control 门槛。

### 阶段 C：目标函数/原始流保护的设计修订（不是 bugfix）

中心化距离损失、真正独立 private path、显式残差范数限制和源类混合训练属于进一步设计修订，不能与 bugfix 混在一起后宣称旧机制得到证实。应在阶段 B 结果后独立预注册，并由用户决定是否值得追加预算。

若不再投入学习式路线，PRS 可保留为下一探索候选；但应先复核已有 NTOF 实现及 PRS 的正常/合成机制门，不能只按夜间总结自动启动。E6 与既有 RCEC 接近，必须先明确实质差异，不能仅换名称重试。

## 7. 推荐汇报口径

可以写：

> 在 MPDD development seed0 的 1/2/4-shot 上，本次缓存级可学习融合实现未超过 A1；多层静态对照没有稳定总体增益。代码审计发现稀疏损失梯度中断、采样偏置及控制实现问题，故尚不能据此否定支持集条件化融合机制或未运行的 backbone 内部融合。

不应写：

- 全部条件/多个 seed 的验证已经完成；
- 零门恒等测试证明整个训练实现无误；
- 提高稀疏约束也无效，证明 gate 必然常开；
- oracle 的 +0.39 证明有巨大可学习互补性；
- 整个前期融合家族、所有 router 或所有多层表征已经被实验否定。
