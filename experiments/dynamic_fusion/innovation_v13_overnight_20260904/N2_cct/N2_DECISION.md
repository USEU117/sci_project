探针：支持集(k1)自身特征 16×16 网格，锚点=支持单元、容量=每单元公平份额，log 域 Sinkhorn

## 2. 判定（doc27 §6 R0/R1）

- R0：✅ 容量匹配检出"正常样式的复制"（doc27 前提：自由匹配会掩盖复制——六类上 a1_free
  gap≈0 实证）。FP（nuisance）≈0.0002–0.0007 受控；信号随面积单调；置换不变。
- 等价性检查（经验）：两计划容量匹配（cct_i 0.044 / cct_c 0.046）**超过 concat-OT
  （0.024）约 +0.020** → 非 concat-OT 退化；但 JS 耦合相对独立双计划增量 ≈ +0.0015（γ=0.5），
  几乎无增益；且**单分支 DINO 容量（0.079）强于任何双分支方案** → 按 doc27「若只有单分支容量
  有效，记录『匹配改进』，撤下『双分支融合创新』表述」：本探针只支持"单分支容量匹配改进"，
  不支持"双分支协同创新"表述。
- R1 真实性能门（六类真实异常 GT、k1/k2/k4、全对照）：本夜 CPU 预算内未完成 → 标
  **PROVISIONAL / TIME_BUDGET**，不写入胜者候选，不宣称真实 AP 收益。
